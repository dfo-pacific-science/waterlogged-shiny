Barometric Pipeline

Introduction

waterlogged is a data processing package for water data from continuous water data loggers. The goal of water-logged is to streamline the process from raw data to clean data, document quality control processing via logs, and do so without relying on proprietorial software.

This tutorial will guide users through processing data from Onset HOBO barometric pressure loggers (U20).

Setup

This vignette assumes you have already installed waterlogged:

install.packages("pak")
pak::pkg_install("dfo-pacific-science/waterlogged")
library(waterlogged)

Prepare Raw Data

In most cases, there will be data for multiple loggers or downloads for a single station. These need to be bound together to create a single data file for each station.

Also, data needs to be trimmed to the install and removal dates in case loggers were activated prior to install, or if they were removed before downloading the data (which is typically the case).

To do this, you will need 2 things:

  1. Folder containing raw .csv files exported from HOBOware (baro_folder)
    • we recommend keeping csv files from different loggers separate in different folders, and organizing logger folders by year and processing-stage. ie. a file path to the raw water-level logger data would be: “data/waterlevel/2024/raw”
  2. A .csv of metadata (metadata_file) containing:
    • sn serial number of logger
    • site_station_code A unique ID for the station where the logger was deployed
    • timestamp_deployed timestamp of logger deployment
    • timestamp_removed timestamp of logger removal
    • status status of logger (logging, lost, removed)

Define paths to the test data.

metadata_file  <- system.file("extdata/metadata/metadata.csv", package = "waterlogged")
baro_folder    <- system.file("extdata/barometric_pressure/raw", package = "waterlogged")
log_root_folder <- tempdir()

The function bind_logger_files will load all .csv files in the path_to_raw_folder, match loggers with the metadata file, trim logger data by to only those timestamps within install/remove dates, and bind data from loggers by each station/location and year. The raw folder must ONLY contain raw logger CSV files of the same metric (ie. all logger files are from barometric pressure loggers).

To save bound files, specify the path to the desired output folder with the optional variable path_to_output_folder.


baro_bound <- bind_logger_files(
  path_to_raw_folder = baro_folder,
  metadata_path      = metadata_file,
)

# to see the trimmed and re-bound baro dataset, save the first element of the list as a dataframe:
baro_data <- baro_bound[[1]]

# to see summary plot
baro_bound[[2]]


# summarize the trimmed and bound data
cat("Baro data:", nrow(baro_data), "rows,",
    length(unique(baro_data$site_station_code)), "stations\n")
#> Baro data: 25978 rows, 3 stations

Now we have individual files for barometric data at each station and year saved in their respective folders, and a trimmed dataset of all input baro files saved in the environment as baro_data.

Automated Quality Control Protocols

Runs dataset through automated data outlier removal and flags, determined by user-modifiable thresholds. The default thresholds are as follows:

  • temp_high_limit: Temperature readings above this value will be removed and data will be flagged as OUTLIER in flag_code column. Default is 50°C
  • temp_low_limit: Temperature readings below this value will be removed and data will be flagged as OUTLIER in flag_code column. Default is -40°C.
  • pressure_low_limit: Pressure readings below this value will be removed and flagged as OUTLIER in flag_code column. Default is 85 kPa.
  • pressure_high_limit: Pressure readings above this value will be removed and flagged as OUTLIER in flag_code column. Default is 105 kPa.
  • spike_threshold: The maximum allowable difference in pressure between consecutive readings. Labeled as SPIKE in data_flag column. Default is 1.5 kPa.
  • flatline_n: The number of consecutive identical pressure readings that will result in a data_flag label of FLATLINE.

The optional input variable log_root is the path to the desired folder where a CSV file of all QC flags and adjustments are stored, by logger station.

baro_qc <- qc_barometric(
  input_data = baro_data,
  log_root = log_root_folder,
  select_station = unique(baro_data$site_station_code)[1]
)

Visual Review

Creates an interactive multi-panel plot for reviewing the data and either accepting or rejecting automated data flags.

How to read the plot:

  • Light traces = raw values (original, unmodified)
  • Dark traces = adjusted values (after auto QC)
  • Black symbols = flagged data (ice, dry, error)
  • Use the range slider at the bottom to zoom into specific periods
  • Hover over points for exact values and timestamps
plot_qc_timeseries(
  baro_data      = baro_qc,
  select_station = unique(baro_data$site_station_code)[1],
    static=TRUE
)

Accept or reject data flags

Inspect pressure data flagged as flatline in May by click and dragging over the triangle symbol (FLAG_FLATLINE) in the third plot. By hovering your mouse over the first triangle symbol you can extract the timestamp for when the flatline began: “2024-05-19 19:00:00”. Likewise, find the timestamp where the flatline ended: “2024-05-20 10:00:00”. Both temperature and air pressure have constant values for over 12 consecutive hours - this is likely a logging error. We can accept the flag and remove this data using the function adjust_logger_NA. Reason to adjust must be “disturbance” for barometric loggers. A manual note is required to note the reason for data removal, and is stored in the QC log file (within the designated log_root folder).


baro_qc <- adjust_logger_NA(
  input_data       = baro_qc,
  select_station   = unique(baro_data$site_station_code)[1],
  metric           = "barometric",
  reason_to_adjust = "disturbance",
  timestamp_start  = "2024-05-19 19:00:00",
  timestamp_end    = "2024-05-20 10:00:00",
  manual_note      = "Sensor error causing flatline",
  log_root = log_root_folder
)

Final Review

Re-plot the data after all corrections to verify the final result. The adjusted traces should look reasonable with no obvious artifacts. Compare raw (light) vs adjusted (dark) to see exactly what changed.

plot_qc_timeseries(
  baro_data      = baro_qc,
  select_station = unique(baro_data$site_station_code)[1],
  static=TRUE
)

Export Clean Data (v1.0)

Writes the final cleaned data to CSV files, one per station per year.

What gets exported:

  • site_station_code, timestamp (identifiers)
  • airpress_kPa, airpress_kPa_adj (raw and adjusted air pressure in kPa)
  • airtemp_C, airtemp_C_adj (raw and adjusted air temperature)
  • All FLAG_*, OUTLIER_* columns (the full audit trail)
